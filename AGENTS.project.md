# Text2BPMN research and application conventions

- Preserve source-linked requirements, current BPMN snapshots, model/prompt/settings, and billing metadata for audit. Never put credentials in client code, exports, fixtures, screenshots, or Git.
- Distinguish existing PET annotations, independently verified scoped oracle labels, provisional extracted requirements, and LLM agreement. No new human annotation is in the current protocol. Do not call the strong operational checker the ground truth.
- A mutation is not automatically an error. Verify the property and witness; the base is not automatically globally correct. Keep generated natural errors separate from injected ones and group source-family variants in the same split.
- Reducing warning counts does not establish successful repair. Retain originals, check the target property and all prior mandatory requirements in scope, and report remaining unknowns/new violations.
- Canvas assessment must fail closed. Do not reuse export getters that fall back to original XML on readiness/serialization failure; use the strict live getter. Cause of prior bug: best-effort download semantics were incorrectly reused for checker evidence.
- Keep P0/P1/P2 inputs/schema/tools equal and change only intended prompt components. Disable or document native reasoning; do not interpret structured evidence as a faithful hidden chain of thought.
- Pilot cascade routing is an uncalibrated heuristic. Report actual cost, coverage, errors and unknowns; do not claim non-inferiority or production access control from process-local admission.
- Freeze execution code before launching experiments. Cause of the 2026-11-17 pilot reproducibility issue: an oracle fix was saved after the paid process had loaded the earlier runner. Finish tests, snapshot runner/generator/checker/fixture hashes, and coordinate a source freeze before launch; do not edit execution code while the run is active. If an oracle correction is unavoidable, preserve the original outcomes and replay saved candidates offline with an explicit old/new audit; never imply post-run hashes prove startup code, rerun paid calls silently, or change target specifications after seeing outputs. Include shared-end XOR cases in oracle tests; multiple incoming alternative flows alone do not imply concurrency.
- Run `npm run typecheck`, `npm run build`, BPMN tests, checker tests, and dev/production browser QA for this feature. The checked-in template's full script suite additionally assumes untracked `.grok` platform resources; report baseline environment failures rather than manufacture fixtures or claim those checks passed.
- Benchmark transport lesson (2026-11-17): the first PET flow benchmark attempt used `openclaw infer model run` without forcing `response_format`, so JSON-format failures would have confounded model quality with transport settings. For checker comparisons, pin the same JSON response format, output cap, provider routing, reasoning setting and schema for every cell; smoke-test both models before the frozen paid run. Preserve aborted attempt metadata separately and never merge it into the final metrics.
